# Contributing

Before opening a pull request, read and follow the project working rules:

- [docs/research/03_working_rules_and_pr_policy.md](docs/research/03_working_rules_and_pr_policy.md)

Key requirements:

- Keep one pull request close to one phase, step, or checkpoint decision.
- Do not mix research claims, scenario design, evaluation criteria, implementation changes, and experiment results unless the PR explains why it cannot be split.
- Record changes to design coverage in `docs/coverage_ledger.md` once the coverage ledger exists.
- Keep LLM logs as evidence for hypothesis generation, not as direct proof of human social behavior.
